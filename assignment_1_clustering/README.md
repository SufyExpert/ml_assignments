# Assignment 2 — Customer Segmentation with KMeans, DBSCAN, and PCA

An unsupervised-learning project that groups credit card customers by behavior — spending,
payments, cash advances, credit usage — using two different clustering algorithms, plus PCA for
visualization. Every preprocessing and modeling decision is explained inline in the notebook.

---

## 1. Dataset

**Credit Card Dataset for Clustering**, hosted on Kaggle:

🔗 **https://www.kaggle.com/datasets/arjunbhasin2013/ccdata**

| Requirement | This dataset |
|---|---|
| Domain | Credit card customer behavior (transaction/spending data) ✅ |
| Numerical features | 17 numeric columns — balance, purchases, cash advances, credit limit, payments, tenure, and more (≥ 4 required ✅) |
| Identifiers | `CUST_ID` — a unique string, removed before clustering |
| Rows | ~8,950 customers |
| Missing values | Real ones — `CREDIT_LIMIT` (1 row), `MINIMUM_PAYMENTS` (~313 rows) — so missing-value handling is a genuine decision, not a formality |

### Why this dataset
It's essentially purpose-built for exactly this assignment — nearly every column is already a
meaningful behavioral feature (no need to invent synthetic ones), it's large enough that discovered
clusters mean something, and it has real missing-data quirks worth handling deliberately.

**Other datasets that would also fit**, if you'd rather swap:
- [Mall Customer Segmentation Data](https://www.kaggle.com/datasets/vjchoudhary7/customer-segmentation-tutorial-in-python) — smaller (200 rows), simpler, classic intro dataset (Age, Annual Income, Spending Score)
- [Online Retail II](https://www.kaggle.com/datasets/mashlyn/online-retail-ii-uci) — transactional data you'd aggregate into RFM (Recency, Frequency, Monetary) features yourself
- [E-Commerce Customer Behavior](https://www.kaggle.com/datasets/imakash3011/customer-personality-analysis) — marketing-flavored, includes purchase channels and campaign response

## 6. Notes / Gotchas

- `FINAL_K` (Section 9) and `FINAL_EPS` / `FINAL_MIN_SAMPLES` (Section 10) are set as explicit
  variables in the notebook, chosen by reading the elbow/silhouette/grid-search evidence above
  them — not computed automatically. If your actual elbow/silhouette plots suggest a different K,
  or the DBSCAN grid search favors different parameters, update those variables before moving on;
  the notebook is written so every downstream cell picks up the change automatically.
- All random processes (KMeans initialization) use `RANDOM_SEED = 42` for reproducibility.
- Never edit the `data/` filename — the notebook expects exactly `data/CC_GENERAL.csv`.
- Unlike Assignment 1, there's no train/val/test split here — clustering is unsupervised, so the
  whole (cleaned, scaled) dataset is used directly.
